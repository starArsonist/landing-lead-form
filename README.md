# landing-lead-form

Продающий лендинг на Django с рабочей формой заявки: проверка телефона, защита от спама и дубликатов, лимит по IP, уведомление в Telegram и список заявок в админке.

Python 3.11+ · Django 5.2 · SQLite · pytest · ruff · uv

> Демо-проект. Идея формы взята из рабочего сайта компании, где я делал приём заявок, но код написан заново: без интеграций с CRM, без привязки к конкретной компании. Компания «Контур», цены, цифры и отзывы на странице вымышленные.

## Что умеет

- **Лендинг**: герой-блок, преимущества, этапы работы, тарифы, отзывы, вопросы и ответы, форма. Адаптивная вёрстка без внешних шрифтов и скриптов, тёмная тема по настройке системы.
- **Форма заявки** работает и без JavaScript (обычный POST с редиректом). С JavaScript отправляется через `fetch`, ошибки показываются под полями, на успех происходит переход на страницу благодарности.
- **Телефон**: принимает `+7 (912) 345-67-89`, `8 912 345 67 89`, `9123456789` и приводит к `+79123456789`. Отсекает слишком короткие, чужие и «все цифры одинаковые» номера. Нормализация написана на стандартной библиотеке, без `phonenumbers`.
- **Защита от спама**:
  - скрытое поле-ловушка: бот получает такой же ответ «успех», но заявка не сохраняется;
  - лимит заявок с одного IP в час (по умолчанию 5), ответ 429;
  - дубликат с тем же телефоном за последние 10 минут не создаёт вторую заявку;
  - заголовок `X-Forwarded-For` игнорируется, пока явно не включён `LEADS_TRUST_X_FORWARDED_FOR`.
- **Уведомление в Telegram** через стандартную библиотеку. Если токен не задан, заявки просто сохраняются. Сбой сети не ломает приём заявки, а токен не попадает в лог.
- **UTM-метки** из адреса страницы сохраняются вместе с заявкой.
- **Админка**: фильтры, поиск, смена статуса прямо в списке.

## Запуск

```bash
uv sync
uv run python manage.py migrate
uv run python manage.py createsuperuser   # по желанию, для админки
uv run python manage.py runserver
```

Откройте http://127.0.0.1:8000/. Чтобы получать уведомления, скопируйте `.env.example` в `.env`, задайте `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` и экспортируйте переменные в окружение.

## Тесты и проверки

```bash
uv run pytest -q
uv run ruff check .
uv run python manage.py makemigrations --check --dry-run
```

Тесты не ходят в сеть. Покрыты нормализация телефона, форма, отправка в Telegram (поддельный транспорт, сетевые ошибки, скрытие токена), приём заявки (дубликаты, лимит, окно времени), представления (JSON и обычный POST, ловушка, CSRF, 429) и совпадение миграций с моделями.

## Структура

```
config/               настройки проекта
leads/phone.py        нормализация телефона (без Django)
leads/notify.py       отправка в Telegram (без Django и сторонних библиотек)
leads/services.py     приём заявки: лимит, дубликаты, уведомление
leads/forms.py        форма и ловушка для ботов
leads/views.py        лендинг, приём заявки, благодарность
leads/templates/      вёрстка страницы
leads/static/         CSS и JavaScript
tests/                pytest + pytest-django
```

## Развёртывание

Для продакшена задайте `DJANGO_DEBUG=0`, `DJANGO_SECRET_KEY`, `DJANGO_ALLOWED_HOSTS`, подключите PostgreSQL, выполните `collectstatic` и отдавайте статику через веб-сервер или WhiteNoise. Если приложение стоит за обратным прокси, включите `LEADS_TRUST_X_FORWARDED_FOR=1` и убедитесь, что прокси сам выставляет этот заголовок.
